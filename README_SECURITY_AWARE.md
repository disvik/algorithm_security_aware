# Оновлення моделі: Security-Aware Dynamic Clustering

До моделі динамічної кластеризації з попередніх робіт додані нові класи для реалізації безпеково-орієнтованої динамічної кластеризації вузлів розподіленої мережі з урахуванням їхнього криптографічного стану.

## 1. `scripts/cls_node.py`

До моделі `Node` додано:

- `crypto_algorithm`
- `crypto_security_level`
- `crypto_policy_version`
- `key_valid`
- `crypto_state`

Також додано методі оцінки криптографічного стану.

## 2. `scripts/crypto_state.py`

Додано клас `CryptoPolicy`, який задає вимоги мережі та визначає стан вузла:

- `VALID`
- `TRANSITIONAL`
- `NON_COMPLIANT`

## 3. `scripts/cls_network.py`

Збережено попередній метод:

`split_into_clusters()`

Він є базовим (baseline).

Додано:

- `assign_crypto_states()` — контролюєма генерація криптографічних конфігурацій;
- `evaluate_crypto_states()`;
- `split_into_security_aware_clusters()` — перший прототип методу, що пропонується.

Новый метод сохраняет количество кластеров и базовые ресурсные характеристики, но добавляет к критерию распределения криптографическое состояние узлов.

## 4. `scripts/alpha_script.py`

Додано режим:

`3 — Security-Aware Dynamic Clustering`

Експериментальний сценарій за замовчуванням створює:

- 70% `VALID`;
- 20% `TRANSITIONAL`;
- 10% `NON_COMPLIANT`.

При цьому вибір майнера та консенсусу поки не змінюються. Це зроблено навмисно: на даному етапі досліджується вплив криптографічного стану на кластеризацію.

## Коментарі

Коефіцієнти штрафу `1` для `TRANSITIONAL` та `2` для `NON_COMPLIANT` є поки параметрами прототипу, а не доведеними оптимальними значеннями. Перед публікацією їх слід досліджувати експериментально.

Наступний етап - побудова baseline-vs-proposed експерименту з однаковими вхідними даними та автоматичним розрахунком метрик безпеки та продуктивності.
