# Обновление модели: Security-Aware Dynamic Clustering

В архив добавлены первые четыре этапа второго пункта диссертации.

## 1. `scripts/cls_node.py`

В модель `Node` добавлены:

- `crypto_algorithm`
- `crypto_security_level`
- `crypto_policy_version`
- `key_valid`
- `crypto_state`

Также добавлены методы оценки криптографического состояния.

## 2. `scripts/crypto_state.py`

Добавлен класс `CryptoPolicy`, который задает требования сети и определяет состояние узла:

- `VALID`
- `TRANSITIONAL`
- `NON_COMPLIANT`

## 3. `scripts/cls_network.py`

Сохранен исходный метод:

`split_into_clusters()`

Он является baseline.

Добавлены:

- `assign_crypto_states()` — контролируемая генерация криптографических конфигураций;
- `evaluate_crypto_states()`;
- `split_into_security_aware_clusters()` — первый прототип предлагаемого метода.

Новый метод сохраняет количество кластеров и базовые ресурсные характеристики, но добавляет к критерию распределения криптографическое состояние узлов.

## 4. `scripts/alpha_script.py`

Добавлен режим:

`3 — Security-Aware Dynamic Clustering`

Экспериментальный сценарий по умолчанию создает:

- 70% `VALID`;
- 20% `TRANSITIONAL`;
- 10% `NON_COMPLIANT`.

При этом выбор майнера и консensus пока не изменяются. Это сделано намеренно: на данном этапе исследуется именно влияние криптографического состояния на кластеризацию.

## Важно

Коэффициенты штрафа `1` для `TRANSITIONAL` и `2` для `NON_COMPLIANT` являются пока параметрами прототипа, а не доказанными оптимальными значениями. Перед публикацией их необходимо исследовать экспериментально.

Следующий этап — построение baseline-vs-proposed эксперимента с одинаковыми входными данными и автоматическим расчетом метрик безопасности и производительности.
